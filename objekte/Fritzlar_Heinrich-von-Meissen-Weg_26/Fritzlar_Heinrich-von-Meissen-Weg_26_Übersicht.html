13 · So nutzt du diese Datei für mehrere Immobilien

Grundprinzip: Jede Immobilie besitzt eine eindeutige Objekt-ID, einen eigenen Ordner und eine eigene HTML-Übersicht. Änderungen werden über den lokalen Projektserver direkt in SQLite gespeichert.
ObjektordnerDatei
objekte/<Objektname>/<Objektname>_Übersicht.html ← diese Datei (nach dem Kopieren umbenennen)
objekte/<nächstes Objekt>/<Objektname>_Übersicht.html (Kopie mit neuen Zahlen)
Wichtig – deine Änderungen sichern: Die Datenbank ist die einzige Quelle. Für die Zusammenarbeit zwischen Rechnern:
  • Nach Änderungen die versionierte immo_datenbank.db mit Git committen und pushen.
  • Auf dem anderen Rechner vor dem Bearbeiten pullen; die DB nicht gleichzeitig auf zwei Rechnern bearbeiten.
  • „💾 State speichern (Download)" erzeugt nur eine JSON-Exportkopie; sie wird nicht eingelesen.
Workflow für eine neue Immobilie:
  • 1. Neuen Objektordner anlegen (z. B. objekte/<Name>/) mit Unterlagen-Ordner
  • 2. Diese HTML-Datei hineinkopieren und mir sagen: „Analysiere das Objekt <Name>"
  • 3. Die Analyse legt eine eindeutige Objekt-ID und einen DB-Datensatz an.
  • 4. Du bearbeitest live – Änderungen werden direkt in SQLite gespeichert.
